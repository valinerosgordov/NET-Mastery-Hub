# Source Generators — генерация кода во время компиляции

> **Roslyn-based components, генерирующие C# code на compile-time на основе AST + metadata.** Замена reflection для performance + AOT-friendly. Incremental generators (.NET 6+), built-in (`[GeneratedRegex]`, `[JsonSerializable]`, `[LoggerMessage]`), как написать свой. Закрывает пробел: «знаю что Source Generators существуют, не понимаю как pipeline работает и почему IIncremental лучше ISource».

## 1. Что это, зачем и когда

### 1.1. Что такое source generator

**Source generator** — Roslyn analyzer-like компонент, который:
1. **Видит** весь syntax tree + semantic model компилируемой сборки.
2. **Генерирует** новые `.cs` файлы.
3. **Compiler** включает их в компиляцию.

Результат — additional code в финальном assembly, **создаваемый автоматически на compile-time**.

```csharp
// User code
public partial class ViewModel
{
    [ObservableProperty]
    private string _name = "";
}

// Generated by source generator (CommunityToolkit.Mvvm)
public partial class ViewModel : INotifyPropertyChanged
{
    public string Name
    {
        get => _name;
        set
        {
            if (!EqualityComparer<string>.Default.Equals(_name, value))
            {
                _name = value;
                OnPropertyChanged(new PropertyChangedEventArgs(nameof(Name)));
            }
        }
    }
    public event PropertyChangedEventHandler? PropertyChanged;
    protected void OnPropertyChanged(PropertyChangedEventArgs e) => PropertyChanged?.Invoke(this, e);
}
```

### 1.2. Зачем

| Проблема | Без SG | С SG |
|----------|--------|------|
| **Boilerplate** | Manual write/copy-paste | Auto-generated из attributes |
| **Reflection cost** | Runtime resolution | Compile-time, native speed |
| **AOT compatibility** | Reflection ломается в Native AOT | Generated code works |
| **Type safety** | Strings + reflection — runtime errors | Compile-time guaranteed |
| **Debugging** | Reflection — black-box | Generated `.cs` viewable |

### 1.3. Главное правило

```
Используй source generator когда:
  - Pattern repeats (boilerplate)
  - Performance critical (replace reflection)
  - AOT-friendly required
  - Compile-time validation возможна

НЕ создавай свой когда:
  - One-off code generation (templates / T4)
  - Runtime customization needed
  - Minimal boilerplate (overhead не оправдывается)

Используй существующие:
  - [GeneratedRegex] (.NET 7+)
  - [JsonSerializable] (.NET 6+)
  - [LoggerMessage]
  - CommunityToolkit.Mvvm ([ObservableProperty], [RelayCommand])
  - Mediator.SourceGenerator (martinothamar)
```

### 1.4. ISourceGenerator vs IIncrementalGenerator

| | ISourceGenerator (.NET 5) | IIncrementalGenerator (.NET 6+) |
|---|---------------------------|----------------------------------|
| API | `Initialize(context)` + `Execute(context)` | Pipeline через `RegisterSourceOutput` |
| Caching | None — re-runs everything | Cached intermediate results |
| Performance | Slow — re-analyses every compilation | Fast — only changed parts |
| IDE | Re-generates на каждой keystroke | Smart re-generation |
| Status | **Deprecated** | **Recommended** |

В 2024+ — **только IIncrementalGenerator**. Старые ISourceGenerator портируй.

### 1.5. Эволюция

| Версия | Что |
|--------|-----|
| **.NET 5 / C# 9** | `ISourceGenerator` introduced |
| **.NET 6 / C# 10** | `IIncrementalGenerator` — caching pipeline |
| **.NET 6** | `[LoggerMessage]` first-party SG |
| **.NET 6** | `JsonSerializerContext` SG для AOT |
| **.NET 7** | `[GeneratedRegex]` для compile-time regex |
| **.NET 7+** | `RegexGenerator`, `LibraryImportGenerator` (replaces DllImport SG) |
| **.NET 8** | Source-generated configuration binding |
| **.NET 8** | Native AOT — source generators essential |
| **.NET 9** | Improved incremental pipeline tooling |

> [!info]- Если ты знаешь Java / Kotlin / Rust / Scala
> **Java:** annotation processors (since Java 6) + Lombok — основной SG ecosystem. Похоже concept: process annotations на compile-time, generate code.
>
> **Kotlin:** KSP (Kotlin Symbol Processing) — modern alternative annotation processors. Pipeline похож на Roslyn IIncrementalGenerator.
>
> **Rust:** `proc_macro` — procedural macros, run на compile-time. Mature ecosystem (`derive(Serialize)`, `derive(Debug)` etc.). C# source generators inspired by Rust в design.
>
> **Scala:** macros (Scala 2 deprecated, Scala 3 — inline + macros). Похожая идея.

> [!question]- Интервью: что такое source generators?
> Roslyn-based components, **генерирующие C# code на compile-time** на основе syntax tree + semantic model компилируемой сборки. Альтернатива **reflection** — performance lookup'ы становятся compile-time (no runtime cost), AOT-friendly. Examples: `[GeneratedRegex]` (.NET 7+), `[JsonSerializable]` (.NET 6+), `[LoggerMessage]`, MVVM Toolkit `[ObservableProperty]`. Source generator анализирует attributes, partial declarations, semantic model, генерирует partial classes / additional types. **IIncrementalGenerator** (NET 6+) — recommended. ISourceGenerator (NET 5) — deprecated.

## 2. Built-in source generators

### 2.1. [GeneratedRegex] (.NET 7+)

```csharp
public partial class Validators
{
    [GeneratedRegex(@"^[a-z]+@[a-z]+\.[a-z]+$", RegexOptions.IgnoreCase)]
    private static partial Regex EmailRegex();
    
    public bool IsEmail(string s) => EmailRegex().IsMatch(s);
}
```

Generator пишет implementation на compile-time. Преимущества:
- **No runtime regex parsing** — all done compile-time.
- **Faster** — specialized code для exact pattern.
- **AOT-friendly** — нет dynamic regex compilation.

```csharp
// Generated (примерно)
private static readonly Regex _emailRegex = new(@"^[a-z]+@[a-z]+\.[a-z]+$", RegexOptions.IgnoreCase | RegexOptions.Compiled);
private static partial Regex EmailRegex() => _emailRegex;
```

### 2.2. [JsonSerializable] (.NET 6+)

```csharp
[JsonSerializable(typeof(User))]
[JsonSerializable(typeof(Order))]
[JsonSerializable(typeof(List<User>))]
internal partial class MyJsonContext : JsonSerializerContext { }

// Использование
var json = JsonSerializer.Serialize(user, MyJsonContext.Default.User);
var u = JsonSerializer.Deserialize<User>(json, MyJsonContext.Default.User);
```

Generator создаёт **type-specific** serializer без reflection. Critical для **Native AOT** (без него JsonSerializer не работает).

### 2.3. [LoggerMessage]

```csharp
public partial class UserService
{
    private readonly ILogger<UserService> _logger;
    
    public UserService(ILogger<UserService> logger) => _logger = logger;
    
    [LoggerMessage(
        EventId = 100,
        Level = LogLevel.Information,
        Message = "User {UserId} logged in from {IpAddress}")]
    static partial void LogUserLogin(ILogger logger, int userId, string ipAddress);
    
    public void OnLogin(int userId, string ip)
    {
        LogUserLogin(_logger, userId, ip);
    }
}
```

Преимущества:
- **Zero allocation** для structured fields (`{UserId}` not concat).
- **Compile-time check** placeholders match parameters.
- **Filter cost minimal** — early exit если log level disabled.

### 2.4. [LibraryImport] (.NET 7+)

```csharp
public partial class NativeMethods
{
    [LibraryImport("user32.dll", StringMarshalling = StringMarshalling.Utf16)]
    public static partial int MessageBox(
        IntPtr hWnd, string text, string caption, int type);
}
```

Замена `[DllImport]`. Generator производит P/Invoke wrapper code — AOT-compatible, type-safe marshalling, faster.

### 2.5. CommunityToolkit.Mvvm

```csharp
public partial class ViewModel : ObservableObject
{
    [ObservableProperty]
    private string _name = "";
    
    [ObservableProperty]
    [NotifyPropertyChangedFor(nameof(FullName))]
    private string _firstName = "";
    
    [ObservableProperty]
    [NotifyPropertyChangedFor(nameof(FullName))]
    private string _lastName = "";
    
    public string FullName => $"{FirstName} {LastName}";
    
    [RelayCommand]
    private async Task SaveAsync()
    {
        await Save();
    }
}
```

`[ObservableProperty]` → public property с `OnPropertyChanged`. `[RelayCommand]` → `ICommand` implementation. WPF/MAUI standard.

### 2.6. Mediator.SourceGenerator (martinothamar/Mediator)

Source-generated альтернатива MediatR: тот же mediator pattern, но dispatch генерируется на compile-time — no reflection, no runtime assembly scanning, AOT-friendly. Актуальность выросла после того, как сам MediatR с v13 перешёл на коммерческую лицензию (Lucky Penny Software; 12.x остаётся Apache 2.0). Два пакета: `Mediator.SourceGenerator` (генератор, `PrivateAssets="all"`) и `Mediator.Abstractions` (интерфейсы `IRequest<TResponse>`, `IRequestHandler<TRequest, TResponse>`, `IMediator`). Stable — 3.0.2.

```csharp
public sealed record Ping(Guid Id) : IRequest<Pong>;
public sealed record Pong(Guid Id);

public sealed class PingHandler : IRequestHandler<Ping, Pong>
{
    public ValueTask<Pong> Handle(Ping request, CancellationToken cancellationToken) =>
        new(new Pong(request.Id));
}
```

```csharp
// Генератор создаёт Mediator-класс + extension AddMediator на compile-time
services.AddMediator(options =>
{
    options.ServiceLifetime = ServiceLifetime.Singleton;   // default — max performance
    options.Assemblies = [typeof(Ping)];                   // где искать messages/handlers
});

var pong = await mediator.Send(new Ping(Guid.NewGuid()));
```

Handlers регистрируются в DI сгенерированным `AddMediator` автоматически. `ValueTask<TResponse>` вместо `Task<TResponse>` — меньше аллокаций на синхронных путях.

### 2.7. Microsoft.Extensions.Configuration source-gen (.NET 8+)

```xml
<PropertyGroup>
  <EnableConfigurationBindingGenerator>true</EnableConfigurationBindingGenerator>
</PropertyGroup>
```

```csharp
// Обычный POCO — partial НЕ нужен
public sealed class AppConfig
{
    public string ConnectionString { get; init; } = "";
    public int MaxRetries { get; init; } = 3;
}

// Вызов Configuration.Get<AppConfig>() / Bind() перехватывается interceptor'ом
```

В отличие от классических SG, которые дописывают partial-часть типа, binder-генератор работает через **C# interceptors** (C# 12): перехватывает call sites `Get<T>()` / `Bind()` / `Configure<T>()` и подставляет generated-код вместо reflection-based binding. Изменения в user-коде не нужны — включается MSBuild-property (в Native AOT web-шаблонах включён по умолчанию). AOT-essential.

> [!question]- Интервью: чем `[GeneratedRegex]` лучше `new Regex()`?
> 1) **No runtime parsing** — pattern компилируется на compile-time, generated method возвращает уже built Regex. 2) **Faster** — specialized code для exact pattern (vs general regex engine). 3) **AOT-compatible** — Native AOT не позволяет dynamic regex compilation. 4) **Static analyzer warnings** — compile-time validation pattern syntax. 5) **Cached static instance** автоматически. Best practice 2024+: `partial Regex EmailRegex()` через `[GeneratedRegex]` вместо `private static readonly Regex _email = new(...)`.

## 3. Consumer perspective — как использовать

### 3.1. Установка через NuGet

```xml
<ItemGroup>
  <PackageReference Include="CommunityToolkit.Mvvm" Version="8.2.0" />
  <PackageReference Include="Mediator.SourceGenerator" Version="3.0.2" PrivateAssets="all" />
  <PackageReference Include="Mediator.Abstractions" Version="3.0.2" />
</ItemGroup>
```

Source generator **packaged inside** NuGet — auto-registered Roslyn'ом.

### 3.2. partial class / method обязательны

```csharp
// ❌ Не работает — generator не может extend non-partial
public class MyClass
{
    [ObservableProperty]
    private string _name = "";
}

// ✅ Partial — generator добавляет другую часть
public partial class MyClass
{
    [ObservableProperty]
    private string _name = "";
}
```

Generator создаёт **second partial part** того же class. Compiler merges.

### 3.3. Просмотр generated code

В **Visual Studio**: Solution Explorer → Project → **Dependencies** → **Analyzers** → раскрыть, найти generator → раскрыть → generated `.cs` files.

В **Rider**: Project → Generated Code в Solution view.

Через `<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>`:
```xml
<PropertyGroup>
  <EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
  <CompilerGeneratedFilesOutputPath>$(BaseIntermediateOutputPath)Generated</CompilerGeneratedFilesOutputPath>
</PropertyGroup>
```

Generated `.cs` файлы в `obj/Debug/net8.0/Generated/`.

### 3.4. Debugging generated code

Можно **breakpoint** в generated code. Step into работает.

### 3.5. Build performance impact

Source generators **запускаются на каждой compilation**. ISourceGenerator (legacy) — slow. **IIncrementalGenerator** caches results — fast for incremental builds.

```
| Project size | Without SG | With SG (incremental) |
|--------------|------------|------------------------|
| Small (~100 files) | 2s | 2.1s |
| Medium (~1000 files) | 15s | 16s |
| Large (~10000 files) | 60s | 65s |
```

~5% overhead для well-written incremental generators.

### 3.6. Avoid version conflicts

```xml
<PackageReference Include="CommunityToolkit.Mvvm" Version="8.2.0" />
<PackageReference Include="Microsoft.CodeAnalysis.CSharp" Version="4.8.0" />
```

Source generators target specific Roslyn version. Mismatch = build errors. Обычно match Visual Studio Roslyn version.

> [!question]- Интервью: почему source generator требует `partial class`?
> Source generator создаёт **второй partial part** того же class. C# compiler merges все partials в один class. Без `partial` нельзя extend existing class — создание класса с тем же именем = compile error. Pattern: user пишет `public partial class ViewModel { [ObservableProperty] private string _name; }`, generator пишет `public partial class ViewModel { public string Name { get; set; } }`. После compile — один class с обоими parts. Также partial methods — declaration в одном файле, implementation в другом (через generator).

## 4. Roslyn fundamentals

### 4.1. SyntaxTree

**SyntaxTree** — AST source code. Node types:
- `CompilationUnitSyntax` — root (whole file).
- `NamespaceDeclarationSyntax`
- `ClassDeclarationSyntax`
- `MethodDeclarationSyntax`
- `PropertyDeclarationSyntax`
- `AttributeSyntax`
- ... etc.

```csharp
SyntaxTree tree = CSharpSyntaxTree.ParseText(@"
    public class Foo
    {
        public int X { get; set; }
    }
");

CompilationUnitSyntax root = tree.GetCompilationUnitRoot();
ClassDeclarationSyntax foo = root.DescendantNodes().OfType<ClassDeclarationSyntax>().First();
PropertyDeclarationSyntax xProp = foo.Members.OfType<PropertyDeclarationSyntax>().First();
```

### 4.2. SemanticModel

**SemanticModel** — typed view над syntax tree. Resolves type references, attribute targets, declarations.

```csharp
INamedTypeSymbol classSymbol = semanticModel.GetDeclaredSymbol(classDeclaration);
ITypeSymbol returnType = semanticModel.GetTypeInfo(expression).Type;
ImmutableArray<AttributeData> attrs = symbol.GetAttributes();
```

Symbols — semantic representation (vs syntactic). `ClassDeclarationSyntax` (raw text) vs `INamedTypeSymbol` (resolved type).

### 4.3. SyntaxNode hierarchy

```
SyntaxNode (abstract)
├── ExpressionSyntax
│   ├── BinaryExpressionSyntax
│   ├── InvocationExpressionSyntax
│   ├── MemberAccessExpressionSyntax
│   └── ...
├── StatementSyntax
│   ├── BlockSyntax
│   ├── IfStatementSyntax
│   ├── ForStatementSyntax
│   └── ...
├── DeclarationSyntax
│   ├── ClassDeclarationSyntax
│   ├── MethodDeclarationSyntax
│   ├── PropertyDeclarationSyntax
│   └── ...
└── TypeSyntax
    ├── PredefinedTypeSyntax (int, string)
    ├── IdentifierNameSyntax (UserClass)
    └── GenericNameSyntax (List<int>)
```

### 4.4. Symbol hierarchy

```
ISymbol
├── INamedTypeSymbol (class, struct, interface, enum, delegate)
├── IMethodSymbol
├── IPropertySymbol
├── IFieldSymbol
├── IParameterSymbol
├── ILocalSymbol
└── INamespaceSymbol
```

### 4.5. Visitor / RewriteVisitor

```csharp
public class ClassFinder : CSharpSyntaxWalker
{
    public List<ClassDeclarationSyntax> Classes { get; } = new();
    
    public override void VisitClassDeclaration(ClassDeclarationSyntax node)
    {
        Classes.Add(node);
        base.VisitClassDeclaration(node);   // recurse
    }
}

var finder = new ClassFinder();
finder.Visit(root);
foreach (var c in finder.Classes) Console.WriteLine(c.Identifier);
```

### 4.6. Tools

- **SharpLab** — sharplab.io — see compiler output / generated code interactively.
- **Roslyn Quoter** — see how Roslyn API constructs syntax tree.
- **Source.NET** — source.dot.net — Roslyn source code browse.

> [!question]- Интервью: чем SyntaxTree отличается от SemanticModel?
> **SyntaxTree** — AST raw source code. Чисто **syntactic** representation. Не знает что такое `User` — это просто `IdentifierNameSyntax`. **SemanticModel** — typed view над syntax tree. **Resolves**: type references, method overloads, attribute targets, references between symbols. Знает что `User` это class в namespace X с N members. Source generator работает с **обоими**: syntax для structural analysis (find all classes с attribute), semantic для resolving types (что такое тип параметра конкретно). API: `compilation.GetSemanticModel(syntaxTree)` → `model.GetDeclaredSymbol(node)` или `model.GetTypeInfo(expression)`.

## 5. IIncrementalGenerator pipeline

### 5.1. Минимальный generator

```csharp
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp.Syntax;

[Generator]
public class HelloGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        context.RegisterPostInitializationOutput(ctx =>
        {
            ctx.AddSource("Hello.g.cs", """
                namespace Generated;
                
                public static class Hello
                {
                    public static string Greet() => "Hello from generator!";
                }
                """);
        });
    }
}
```

`RegisterPostInitializationOutput` — выполняется один раз, **до** анализа syntax. Производит fixed code.

### 5.2. Pipeline architecture

```
SyntaxProvider (filter syntax)
    ↓
SemanticProvider (extract semantic info)
    ↓
Combine с CompilationProvider (whole-compilation context)
    ↓
RegisterSourceOutput (generate code)
```

Каждый этап **cacheable**. Если input не изменился — cached output reused.

### 5.3. Полный pipeline пример

```csharp
[Generator]
public class AutoConstructorGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        // 1. Найти все классы с [AutoConstructor] attribute
        IncrementalValuesProvider<ClassDeclarationSyntax> classes = context.SyntaxProvider
            .CreateSyntaxProvider(
                predicate: static (node, _) => node is ClassDeclarationSyntax c && c.AttributeLists.Count > 0,
                transform: static (ctx, _) => (ClassDeclarationSyntax)ctx.Node)
            .Where(c => HasAutoConstructorAttribute(c));
        
        // 2. Combine с compilation для semantic model
        IncrementalValueProvider<(Compilation Compilation, ImmutableArray<ClassDeclarationSyntax> Classes)> compilationAndClasses =
            context.CompilationProvider.Combine(classes.Collect());
        
        // 3. Generate
        context.RegisterSourceOutput(compilationAndClasses,
            (spc, source) => Execute(source.Compilation, source.Classes, spc));
    }
    
    static bool HasAutoConstructorAttribute(ClassDeclarationSyntax c) =>
        c.AttributeLists.Any(al => al.Attributes.Any(a => a.Name.ToString().Contains("AutoConstructor")));
    
    static void Execute(Compilation compilation, ImmutableArray<ClassDeclarationSyntax> classes, SourceProductionContext context)
    {
        foreach (var classDecl in classes)
        {
            var model = compilation.GetSemanticModel(classDecl.SyntaxTree);
            var symbol = model.GetDeclaredSymbol(classDecl);
            if (symbol is not INamedTypeSymbol namedType) continue;
            
            var fields = namedType.GetMembers()
                .OfType<IFieldSymbol>()
                .Where(f => f.IsReadOnly && !f.IsStatic)
                .ToList();
            
            var source = GenerateConstructor(namedType, fields);
            context.AddSource($"{namedType.Name}.AutoConstructor.g.cs", source);
        }
    }
    
    static string GenerateConstructor(INamedTypeSymbol type, List<IFieldSymbol> fields)
    {
        var parameters = string.Join(", ", fields.Select(f => $"{f.Type.ToDisplayString()} {f.Name.TrimStart('_')}"));
        var assignments = string.Join("\n        ", fields.Select(f => $"this.{f.Name} = {f.Name.TrimStart('_')};"));
        
        return $$"""
            namespace {{type.ContainingNamespace.ToDisplayString()}};
            
            partial class {{type.Name}}
            {
                public {{type.Name}}({{parameters}})
                {
                    {{assignments}}
                }
            }
            """;
    }
}
```

### 5.4. CreateSyntaxProvider — filter + transform

```csharp
context.SyntaxProvider.CreateSyntaxProvider(
    // Stage 1: fast structural check (called часто — must be fast!)
    predicate: static (node, ct) => node is ClassDeclarationSyntax c && c.AttributeLists.Count > 0,
    
    // Stage 2: heavier semantic work (called только если predicate true)
    transform: static (ctx, ct) =>
    {
        var classDecl = (ClassDeclarationSyntax)ctx.Node;
        var symbol = ctx.SemanticModel.GetDeclaredSymbol(classDecl);
        return new ClassInfo(symbol, ...);
    });
```

`predicate` — вызывается **на каждом node syntax tree**. Должен быть **очень быстрым** (без semantic model access).

`transform` — вызывается только для предикатно true. Может использовать semantic model.

### 5.5. ForAttributeWithMetadataName (.NET 7+)

```csharp
// Optimized для attribute-based generators
IncrementalValuesProvider<ClassDeclarationSyntax> classes = context.SyntaxProvider
    .ForAttributeWithMetadataName(
        "MyNamespace.AutoConstructorAttribute",
        predicate: static (node, _) => node is ClassDeclarationSyntax,
        transform: static (ctx, _) => (ClassDeclarationSyntax)ctx.TargetNode);
```

`ForAttributeWithMetadataName` — Roslyn provides indexed lookup, **много faster** чем manual filter. Use when filtering by attribute.

### 5.6. Combine providers

```csharp
// Combine source files + compilation
var combined = classes.Collect().Combine(context.CompilationProvider);
combined.Select(/* ... */);

// Combine с AdditionalFile (custom files in project)
var jsonFiles = context.AdditionalTextsProvider
    .Where(f => f.Path.EndsWith(".json"));

// Combine multiple
var triple = classes.Combine(jsonFiles.Collect()).Combine(context.CompilationProvider);
```

### 5.7. Cancellation

```csharp
transform: static (ctx, ct) =>
{
    ct.ThrowIfCancellationRequested();   // important! IDE cancels часто
    var symbol = ctx.SemanticModel.GetDeclaredSymbol(...);
    ct.ThrowIfCancellationRequested();
    return ...;
}
```

IDE cancels generator runs (на keystroke). Periodic cancellation check — must.

> [!question]- Интервью: что такое IIncrementalGenerator pipeline?
> Структура composable providers, где каждый этап **cacheable**: 1) **SyntaxProvider** — filter syntax nodes (predicate fast, transform heavier). 2) **CompilationProvider** — whole-compilation context. 3) **AdditionalTextsProvider** — non-`.cs` files. **Combine** providers через `.Combine(...)`, **Collect** для aggregating. **`RegisterSourceOutput`** — final stage: produces `.cs` files. Cache key — input data (если не изменилось — output reused). Best practice: predicate должен быть **очень fast** (millions calls per compilation), transform — heavier OK. **`ForAttributeWithMetadataName`** (.NET 7+) — optimized lookup для attribute-based generators.

## 6. AddSource — генерируемый текст

### 6.1. Правила naming

```csharp
context.AddSource("MyClass.g.cs", source);
context.AddSource("MyClass.AutoConstructor.g.cs", source);
context.AddSource("MyNamespace.MyClass.g.cs", source);
```

- Suffix `.g.cs` — convention для generated.
- Unique name per source (collision = error).
- Recommend qualifying с namespace для avoid collisions.

### 6.2. Raw string literals для templates

```csharp
var source = $$"""
    // <auto-generated/>
    #nullable enable
    
    namespace {{namespaceName}};
    
    partial class {{className}}
    {
        public {{className}}({{parameters}})
        {
            {{assignments}}
        }
    }
    """;

context.AddSource($"{className}.g.cs", source);
```

`$$"""..."""` (two `$`) — interpolation через `{{x}}`, single `{` literal. Идеально для code templates.

### 6.3. Header `<auto-generated/>`

```csharp
var source = """
    // <auto-generated/>
    // This file is generated by SourceGenerator. Do not modify.
    
    #nullable enable
    """;
```

`<auto-generated/>` — tells **analyzers** skip this file (no formatting checks, no style warnings).

### 6.4. Nullable annotations

```csharp
var source = """
    // <auto-generated/>
    #nullable enable
    
    namespace ...
    """;
```

`#nullable enable` — generated code participates в NRT analysis. Без этого — NRT off в generated.

### 6.5. Файл per type vs combined

```csharp
// Per-type — IDE-friendly, easier debugging
foreach (var classInfo in classes)
{
    context.AddSource($"{classInfo.Name}.g.cs", GenerateForClass(classInfo));
}

// Combined — performance (less IDs to track)
var combined = string.Join("\n", classes.Select(GenerateForClass));
context.AddSource("Generated.g.cs", combined);
```

Best practice: **per-type для maintainability** unless thousands of types.

### 6.6. Diagnostic reports

```csharp
context.RegisterSourceOutput(provider, (spc, data) =>
{
    if (data.Field.Type.IsValueType && data.Field.Type.NullableAnnotation == NullableAnnotation.None)
    {
        spc.ReportDiagnostic(Diagnostic.Create(
            new DiagnosticDescriptor(
                "MYGEN001",
                "Value type без default",
                "Field {0} требует default value",
                "MyGenerator",
                DiagnosticSeverity.Warning,
                isEnabledByDefault: true),
            data.Field.Locations.FirstOrDefault(),
            data.Field.Name));
        return;
    }
    
    spc.AddSource(/* ... */);
});
```

Diagnostics — warnings/errors показываются в IDE и build output. Use для validation user code.

> [!question]- Интервью: что такое `<auto-generated/>` header в SG?
> Comment marker (`// <auto-generated/>`) в начале generated `.cs` file. Tells **Roslyn analyzers и code style checks** skip this file. Без него: формирование warnings (CA, IDE rules) на generated код, lint errors. С маркером: analyzers пропускают, focus только на user code. Convention: include в первой line + add `#nullable enable` для NRT. Some generators add комментарий с timestamp + generator version для traceability.

> [!question]- Интервью: почему source generator targets `netstandard2.0`?
> Source generators run внутри **Roslyn compiler**, который сам runs внутри: 1) **Visual Studio** (.NET Framework 4.8 process). 2) **Rider** (.NET Core). 3) **dotnet build** CLI. Чтобы работать во всех — generator assembly должен быть **netstandard2.0** compatible. Targeting `net8.0` — generator не будет загружаться в VS. **Microsoft.CodeAnalysis.CSharp** package — также targeting netstandard2.0. С приходом Native AOT и .NET 8+ generators могут также target newer (specific scenarios), но netstandard2.0 — universal default.

## 8. Example: build complete generator

### 8.1. Goal

Generate `Equals` + `GetHashCode` + `==`/`!=` для классов с `[ValueEquality]` attribute по всем readonly fields.

### 8.2. Attribute (in generator project as POCO)

```csharp
namespace MyGenerators;

[AttributeUsage(AttributeTargets.Class)]
public class ValueEqualityAttribute : Attribute { }
```

(Attribute defined в shared project, referenced consumer.)

### 8.3. Generator

```csharp
using Microsoft.CodeAnalysis;
using Microsoft.CodeAnalysis.CSharp.Syntax;
using System.Collections.Immutable;
using System.Linq;
using System.Text;

[Generator]
public class ValueEqualityGenerator : IIncrementalGenerator
{
    public void Initialize(IncrementalGeneratorInitializationContext context)
    {
        var classes = context.SyntaxProvider.ForAttributeWithMetadataName(
            "MyGenerators.ValueEqualityAttribute",
            predicate: static (node, _) => node is ClassDeclarationSyntax,
            transform: static (ctx, _) => GetClassInfo(ctx));
        
        context.RegisterSourceOutput(classes, GenerateSource);
    }
    
    static ClassInfo? GetClassInfo(GeneratorAttributeSyntaxContext ctx)
    {
        if (ctx.TargetSymbol is not INamedTypeSymbol type) return null;
        
        var fields = type.GetMembers()
            .OfType<IFieldSymbol>()
            .Where(f => f is { IsReadOnly: true, IsStatic: false })
            .Select(f => new FieldInfo(f.Name, f.Type.ToDisplayString()))
            .ToImmutableArray();
        
        return new ClassInfo(
            type.Name,
            type.ContainingNamespace.ToDisplayString(),
            fields);
    }
    
    static void GenerateSource(SourceProductionContext spc, ClassInfo? info)
    {
        if (info == null) return;
        
        var sb = new StringBuilder();
        sb.AppendLine("// <auto-generated/>");
        sb.AppendLine("#nullable enable");
        sb.AppendLine();
        sb.AppendLine($"namespace {info.Namespace};");
        sb.AppendLine();
        sb.AppendLine($"partial class {info.ClassName} : System.IEquatable<{info.ClassName}>");
        sb.AppendLine("{");
        
        // Equals(T other)
        sb.AppendLine($"    public bool Equals({info.ClassName}? other)");
        sb.AppendLine("    {");
        sb.AppendLine("        if (other is null) return false;");
        sb.AppendLine("        if (ReferenceEquals(this, other)) return true;");
        sb.AppendLine("        return " + string.Join(" && ",
            info.Fields.Select(f => $"System.Collections.Generic.EqualityComparer<{f.Type}>.Default.Equals({f.Name}, other.{f.Name})")) + ";");
        sb.AppendLine("    }");
        
        // Equals(object)
        sb.AppendLine($"    public override bool Equals(object? obj) => Equals(obj as {info.ClassName});");
        
        // GetHashCode
        sb.AppendLine("    public override int GetHashCode()");
        sb.AppendLine("    {");
        sb.AppendLine("        var hash = new System.HashCode();");
        foreach (var f in info.Fields)
            sb.AppendLine($"        hash.Add({f.Name});");
        sb.AppendLine("        return hash.ToHashCode();");
        sb.AppendLine("    }");
        
        // == / !=
        sb.AppendLine($"    public static bool operator ==({info.ClassName}? a, {info.ClassName}? b) => a is null ? b is null : a.Equals(b);");
        sb.AppendLine($"    public static bool operator !=({info.ClassName}? a, {info.ClassName}? b) => !(a == b);");
        
        sb.AppendLine("}");
        
        spc.AddSource($"{info.ClassName}.ValueEquality.g.cs", sb.ToString());
    }
}

record ClassInfo(string ClassName, string Namespace, ImmutableArray<FieldInfo> Fields);
record FieldInfo(string Name, string Type);
```

## 9. Performance tuning

### 9.1. Predicate fast

```csharp
// ❌ Slow predicate — string allocation per node
predicate: static (node, _) =>
    node.ToString().Contains("[MyAttribute]")

// ✅ Fast predicate — structural check only
predicate: static (node, _) =>
    node is ClassDeclarationSyntax c && c.AttributeLists.Count > 0
```

Predicate вызывается **миллионы раз** per compilation. Должен быть очень fast (no allocation, no semantic).

### 9.2. Transform минимизирует closure

```csharp
// ❌ Captures self
transform: (ctx, _) => this.HandleNode(ctx)   // closure allocation per call

// ✅ Static — no capture
transform: static (ctx, _) => HandleNode(ctx)
```

`static` lambda — no captured variables → no allocation.

### 9.3. Equatable records для caching

```csharp
// ✅ Records — auto-equality, supports caching
record ClassInfo(string Name, ImmutableArray<FieldInfo> Fields);

// ❌ Class without Equals — no caching
class ClassInfo
{
    public string Name { get; init; }
    public ImmutableArray<FieldInfo> Fields { get; init; }
}
```

Pipeline cache compares **value equality**. Records — automatic. Class — needs Equals override.

### 9.4. ImmutableArray для collections

```csharp
record ClassInfo(string Name, ImmutableArray<FieldInfo> Fields);   // ✅
record ClassInfo(string Name, List<FieldInfo> Fields);              // ❌ — Equals reference, no caching
```

`ImmutableArray<T>` имеет structural equality. `List<T>` — reference. Cache не работает с List.

### 9.5. Avoid string interpolation в hot paths

```csharp
// Better в generator hot path
var sb = new StringBuilder();
sb.Append("class ");
sb.Append(name);
// ...

// vs interpolation (creates intermediate strings)
var s = $"class {name} {{ public {field.Type} {field.Name} {{ get; }} }}";
```

Generator runs many times. Allocations накапливаются.

> [!question]- Интервью: что значит "incremental" в IIncrementalGenerator?
> **Pipeline cache** — каждый этап (provider) caches results. Если input не изменился — output reused, не recomputed. Cache key — value equality of input. Records → automatic equality. `ImmutableArray<T>` → structural equality. **Important**: используй records / ImmutableArray в pipeline data types — иначе cache не работает (reference equality на List/class). **Predicate** должен быть очень fast — вызывается на каждом syntax node every compilation. **Transform** heavier OK — only when predicate true. IDE re-runs generators **на каждой keystroke**, incremental критичен для responsiveness.

## 10. Best practices

### 10.1. Generator design

- ✅ **`IIncrementalGenerator`** only (ISourceGenerator deprecated).
- ✅ **`netstandard2.0`** target.
- ✅ **`ForAttributeWithMetadataName`** для attribute-based filters.
- ✅ **Records / ImmutableArray** в pipeline data.
- ✅ **`static` lambdas** для no captures.
- ✅ **Cancellation token check** periodic.
- ✅ **Per-type generated files** для maintainability.

### 10.2. Code quality

- ✅ **`<auto-generated/>` header** + `#nullable enable`.
- ✅ **Fully qualified names** — `System.IEquatable<T>` not `IEquatable<T>`.
- ✅ **Diagnostic reports** для invalid input.
- ✅ **Snapshot tests** через `Verify.SourceGenerators`.
- ✅ **MSBuild ReportAnalyzer** для perf measure.

### 10.3. Testing

- ✅ **Unit test pipeline** через `CSharpGeneratorDriver`.
- ✅ **Verify** snapshot tests.
- ✅ **Edge cases** — empty class, no fields, nullable annotations.
- ✅ **Diagnostic tests** — invalid input → expected diagnostic.

### 10.4. Не делай

- ❌ I/O в generator (file/network) — slow, breaks caching.
- ❌ Random / time-based output — inconsistent.
- ❌ Mutable state в generator instance.
- ❌ Throw exceptions — use Diagnostic.Report.
- ❌ Generator targets `net8.0` — не загрузится в VS.

Что делать?

│   ├── AOT-friendly required?
│   ├── ⇒ IIncrementalGenerator + ForAttributeWithMetadataName
│   └── netstandard2.0 + Microsoft.CodeAnalysis.CSharp

## 13. Common pitfalls

### 13.1. Не partial — generator не может extend

```csharp
public class MyClass   // ❌ no partial
{
    [ObservableProperty]
    private string _name = "";
}
```

**Фикс:** `public partial class MyClass`.

### 13.2. Generator targets net8.0

```xml
<TargetFramework>net8.0</TargetFramework>   <!-- ❌ -->
```

**Механизм:** Visual Studio runs Roslyn в .NET Framework process — не может load net8.0 assembly.

**Фикс:** `<TargetFramework>netstandard2.0</TargetFramework>`.

### 13.3. ISourceGenerator (deprecated)

```csharp
public class OldGen : ISourceGenerator   // ❌ deprecated
{
    public void Execute(GeneratorExecutionContext context) { /* ... */ }
    public void Initialize(GeneratorInitializationContext context) { }
}
```

**Фикс:** port to `IIncrementalGenerator`.

### 13.4. Slow predicate

```csharp
predicate: static (node, _) =>
    node.ToString().Contains("[MyAttr]")   // ❌ allocation per node
```

**Фикс:** structural check — `node is ClassDeclarationSyntax c && c.AttributeLists.Count > 0`.

### 13.5. Mutable state в pipeline data

```csharp
class ClassInfo
{
    public List<string> Fields { get; set; } = new();   // ❌ List<T> reference equality
}
```

**Фикс:** record + ImmutableArray.

### 13.6. Throw exception в generator

```csharp
transform: static (ctx, _) =>
{
    if (...) throw new InvalidOperationException();   // ❌ build error
}
```

**Фикс:** `Diagnostic.Create(...)` + report.

### 13.7. I/O в generator

```csharp
transform: static (ctx, _) =>
{
    var contents = File.ReadAllText("config.json");   // ❌ slow + breaks caching
    return Parse(contents);
}
```

**Фикс:** `AdditionalTextsProvider` для project files.

### 13.8. Не unique source name

```csharp
spc.AddSource("Generated.g.cs", source1);
spc.AddSource("Generated.g.cs", source2);   // ❌ collision!
```

**Фикс:** unique names per type.

### 13.9. Generated code без header

```csharp
spc.AddSource("Foo.g.cs", "namespace Foo { /* ... */ }");
// ⚠ analyzers warn на generated code
```

**Фикс:** `// <auto-generated/>` + `#nullable enable`.

### 13.10. Тестирование забыто

Generator работает на одном проекте, ломается на другом — coverage недостаточный. Always **snapshot tests** + edge cases (empty class, generic, nested).

> [!question]- Интервью: топ-3 ошибки при разработке source generator?
> 1) **Не `partial class`** в consumer — generator не может extend, compile error. 2) **Slow predicate** — `node.ToString().Contains(...)` calls millions times, кiller performance. Structural check only. 3) **Mutable state / `List<T>` в pipeline data** — cache не работает (reference equality). Records + `ImmutableArray<T>`. Бонус: targeting `net8.0` вместо `netstandard2.0` — generator не загрузится в Visual Studio. ISourceGenerator (deprecated) — port to IIncrementalGenerator.
